# T3 Code delegation

Use this reference before dispatching a worker in T3 mode. Read the roster and the delegation gate in [../SKILL.md](../SKILL.md) first.

## Discover capabilities

Find the exposed `orchestrator_capabilities`, `delegate_task`, `task_status`, and `task_cancel` tools. Codex may show them with an MCP server prefix such as `t3-code`. Call `orchestrator_capabilities` once per session before the first dispatch, and again only after an error. Pass `{"search": "<model id>"}` when the short list omits a roster model.

For each roster row, confirm that the provider instance is enabled, that its `canRunChildTask` is true, that the model ID is listed, and that each option and value appear in the model's option descriptors. A missing provider, model, option, or value needs the user's decision. Never switch to another harness, model, or option value unasked, and never fall back to native subagents for a T3 roster role.

## Dispatch

A Builder dispatch has this argument shape. Replace the request ID and the brief with a stable ID and the complete task packet. Use each persona's exact `target` from the roster for the other roles.

```json
{
  "task": "Complete task packet: worker preamble, persona instructions, objective, ownership, constraints, proofs, and required evidence.",
  "target": {
    "providerInstanceId": "claudeAgent",
    "model": "claude-sonnet-5-5",
    "options": {"effort": "high"}
  },
  "role": "implementation",
  "mode": "async",
  "clientRequestId": "<feature>-builder-r1"
}
```

`role` names the task's purpose: `research` for a Scout, `implementation` for a Builder, `review` for a Verifier, and `design` or `general` for an Oracle. It never selects the model.

The child starts with only `task`. It loads its own harness's instruction files and skills from the checkout, but none of this conversation. Put every applicable constraint, decision, and persona instruction in the brief.

Omitted isolation shares the parent's checkout, which the single-writer rule in the skill requires. Use `isolation: "worktree"` only when a separate checkout is needed and the user authorized it. A worktree starts from the parent's local commit, runs project setup, and omits uncommitted edits. Choose the workspace in the dispatch call; never ask a worker to create one.

Check the returned `providerInstanceId`, `model`, and `options` against the roster, comparing options by `id` and `value`. A mismatch fails the configuration check. Cancel the mismatched task, keep its task ID and any partial changes as evidence, and resolve the mismatch before dependent work.

## Track tasks and rounds

Keep each `taskId`, `clientRequestId`, requested and returned target, assignment scope, status, and final evidence. Record a worker in review records as `<persona>:<taskId>`, for example `builder:<taskId>` and `verifier:<taskId>`.

Prefer `mode: "async"`. Completion notifies the parent, so do independent work and then yield. Follow the `next` hint a call returns. Use `task_status` with `{"taskId": "<id>"}` only when a result is needed mid-turn, and never poll in a loop or with a watcher. A `mode: "wait"` timeout ends the parent's wait, not the child; keep its task ID and never dispatch a duplicate.

Use `task_cancel` with `{"taskId": "<id>"}` for a task you replace or no longer need. Cancellation does not undo edits, so inspect partial changes before assigning replacement work.

Start every follow-on assignment and review round with a new `delegate_task` call and a fresh `clientRequestId`. Keep that ID across retries of the same round. Supply the original brief, previous findings, responses, and unresolved objections. A fresh Verifier gets no author conversation. Never send work to a returned `childThreadId`, and never start delegated work with thread-launch or thread-send tools. Those address top-level conversations, not tasks.

Children stay leaves, except an Oracle the brief permits to dispatch read-only Scouts. Give that Oracle the Scout's exact `target`. A pending question or approval stays with its decision holder; delegation confers no approval authority.
