# Preserve reusable research

After verifying explorer/librarian results, the root decides whether saving a
report has a concrete future use. Oracle can recommend preservation but remains
read-only. Keep routine lookups, temporary status, easily repeated output, and
findings useful only now in the conversation.

Offer to save when findings support a lasting decision, will likely be reused,
or would be costly to reconstruct. Check existing notes first. Propose an update
only when it adds useful findings or corrects stale evidence. Changing facts
need version/date context, limitations, and a revalidation condition.

Before creating or updating a report, ask the user with a summary of findings,
future use, freshness limits, proposed path, and action. Use the exposed
question tool with a recommended save option. Without a question tool, ask in
the response and wait. Each save requires explicit approval; implementation
approval, silence, and a preselected option do not authorize a report. Continue
independent work while waiting. An explicit user request for that report already
authorizes the requested artifact and destination.

After approval, verify the claims and write one topic-specific Markdown file
under the project's `docs/research/`, unless the user chose another destination.
Settle the destination in the question when no project/workspace is meaningful.
The root writes the report; workers return evidence. Project reports belong
outside global skill folders.

Record the question, scope, date, version context, findings, citations,
contradictions, unknowns, and revalidation conditions. Separate observations,
documented guarantees, and recommendations. Cite substantive claims beside the
claims. Omit unsupported claims or state their gaps. Ask again when verification
materially changes the approved scope or conclusion. Use the available writing
skills. Saving a report does not authorize a commit, push, or external action.
